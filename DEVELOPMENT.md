# Development

Install Go ≥1.26, Node ≥22.12, npm and Hugo ≥0.140. `./dev.sh` builds and starts the static server. `./dev.sh --watch` serves the editor through Vite at localhost:5173. Add `--bridge` to either command to enable optional integration; browser Settings must enable it too. Restart Go after backend changes.

```sh
./scripts/test.sh
./scripts/test.sh --e2e
./build.sh
./bin/visual-nerve --static ./public
```

Install browser test dependencies once: `cd frontend && npx playwright install --with-deps chromium`. PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH selects an existing Chromium binary. E2E uses its own server on 127.0.0.1:4327 and isolated browser contexts, never the user's workspace. The integration fixture opens a browser first; HTTP requests are forwarded to that browser and committed in its IndexedDB. Static/offline scenarios disable integration and verify no graph network requests.

If a local headless browser stops delivering animation frames before a click/tap, `VISUAL_NERVE_E2E_DISABLE_GPU=1` selects software rendering for a diagnostic run. It changes the test browser launch only; it does not skip assertions, force input, disable tracing or change application code. Keep an installed browser version fixed throughout a long run. Ordinary 2D mobile tests use normal graphics options; software WebGL flags are scoped to the separate relief test. CI uses its installed Playwright browser with the default configuration.

Failed CI runs retain available browser diagnostics for seven days in the `playwright-failure-<run-id>-<attempt>` artifact. Download it from the run's **Artifacts** section or with `gh run download <run-id> -n playwright-failure-<run-id>-<attempt> -D /tmp/visualnerve-ci-diagnostics`. It includes the HTML report, failure screenshots, traces and test attachments; video export tests also save the exported movie. From `frontend`, open the report with `npx playwright show-report /tmp/visualnerve-ci-diagnostics/playwright-report` or a failed test's `trace.zip` with `npx playwright show-trace /tmp/visualnerve-ci-diagnostics/test-results/<test-directory>/trace.zip`. Cancelled runs and failures before browser tests produce no browser artifact.

Unit tests use fake-indexeddb, real Dexie/native transactions and native Node WebCrypto. They verify logical schema 8 and its 14 stores, physical vault schema 1, upgrades, authenticated encryption, corrupt/wrong credentials, chunks, atomic verified transfer, content-key rotation, session revocation, templates, graph ordering/metadata/viewport, versions, rollback, hierarchy/groups, owner reassignment, backup/restore, saved history, simulation archives, collisions and optimistic controller behavior. Browser tests exercise editing, deep mind maps, touch/mobile, multiple tabs, native encrypted storage, offline reload, layout, exports, restore and optional REST/MCP integration. Go tests verify static serving, bridge lifetime, HTTP/stdio MCP protocols, host/origin/token checks and canonical DTO validation.

Persistence changes belong in `frontend/src/storage` and the vault codecs/session owners in `frontend/src/security`. Use the scoped `WorkspaceStorage` contract for application code; never bypass it with a raw database or recapture a capability after an await. Acquire the originating operation before imports, saves, worker waits or other asynchronous work, then check it before private publication and commits. The legacy backend uses versioned Dexie upgrades; physical vault envelopes and logical schema evolution have separate versions and authenticated validation. Preserve older installed data and test both backends. Cryptography must complete outside short native IndexedDB transactions. Keep canonical models, integration DTOs, `docs/openapi.yaml` and contract tests consistent. Multi-entity operations must roll back completely on failure. Use bulk operations and diagram/external-ID indexes rather than individual writes per entity.

Add node kinds through the canonical type list and nodes/registry.tsx. Preserve separation of graph semantics, coordinates and rendering. Run `npm run format` for frontend files; format:check is included in the test script. Use gofmt for Go. build.sh regenerates OpenAPI and license notices, bundles React, builds Hugo and its offline shell, then compiles the static/bridge binary.

Configuration: VISUAL_NERVE_ADDR, VISUAL_NERVE_STATIC_DIR and optional VISUAL_NERVE_BRIDGE_TOKEN. Runtime flags: --addr, --static, --dev and --bridge. The server has no database/data-directory configuration. Build artifacts, dependency directories, browser reports and local environment files are ignored by git.

## Origins and privacy tests

`http://localhost:1313`, `http://localhost:5173`, `http://localhost:4317`, `http://127.0.0.1:4317` and `https://visualnerve.example.com` each have separate IndexedDB databases. Development data does not appear in production. Export/import deliberately when changing profile or origin. Do not use a real user browser profile in tests.

The browser suite also starts a read-only HTTPS static fixture on port 4340, the encrypted app fixture with its actual blocking headers on 4341, and a separate loopback TLS MCP bridge on 4329. `public-app.test` resolves to loopback only inside isolated Chromium test processes; no public DNS or AWS resources are created. Self-signed test certificates and relaxed certificate checks are test-only. Real TLS bridges require trusted certificates; ordinary browser local-network permissions also apply when using loopback HTTP. Persistent-profile acceptance tests create and delete temporary browser profiles outside the repository and actually close/reopen Chromium.

Real neural speech acceptance is a separate explicit download: `PIPER_HIGH_VOICES=1 node scripts/acceptance-piper.mjs` prepares all 35 steps from the midpoint, reuses every clip, previews selected actual high-quality models and decodes a narrated movie. Normal CI uses pinned pronunciation configurations and controlled audio fixtures. Post-deployment `VN_PRODUCTION_SMOKE=1` tests use real public TLS/DNS, fresh disposable browser contexts and an empty local bridge; their configuration disables credential-bearing traces/screenshots and certificate or network-policy bypasses. The disposable production profile accepts Chrome’s normal loopback-network permission only for `https://app.visualnerve.com` in its own browser context; MCP access still requires a separate grant in Settings, and TLS/CSP/network protections remain enabled. See [speech](docs/SPEECH.md), [encrypted acceptance](docs/acceptance/2026-10-08-encrypted-workspace.md) and [app publication](docs/APP_ORIGIN_DEPLOYMENT.md).

Privacy scenarios prove explicit consent cannot be dismissed/bypassed, same-URL profile isolation, no remote persistence requests, manual backup portability, confirmed replacement/deletion, read-only/write/Off MCP and browser-closed errors. Normal browser requests are audited for method and destination. Schema tests cover v1/v3 upgrades, replacement rollback and excluded grants/consent. Deployment tests verify canonical redirects, read-only infrastructure and rejection of backups in the app bundle. See docs/REQUIREMENTS.md and docs/ACCEPTANCE.md.

Additional runtime flags: --allowed-origin (repeatable), --tls-cert and --tls-key. Environment counterparts are VISUAL_NERVE_ALLOWED_ORIGINS (comma-separated), VISUAL_NERVE_TLS_CERT and VISUAL_NERVE_TLS_KEY. Bridge use stays loopback-only. Static hosting needs no Go process. See [deployment](docs/DEPLOYMENT.md).

## Export and import contracts

PNG/PDF and native SVG use the isolated canonical 2D renderer even when the editor is in 3D. Preserve the export-local graph/model context, scopes, saved pen layer and labels when changing node renderers. SVG remains vector text/shapes/paths rather than an embedded screenshot; it rejects excessive work/output and normalizes illegal XML characters. JSON/Markdown/SVG responses from `POST /export` are all JSON. See [export formats](EXPORT_FORMAT.md).

ZIP analysis uses a captured browser-local `project-source-file-limit`: default 500, configurable from 500 to 10,000. It is independent of the byte import limit; raising it does not raise archive-entry, line, object, connection or deadline bounds. Backups exclude both local limits and restore preserves destination choices. Update UI, API/MCP capability discovery, OpenAPI, focused regressions and [code import documentation](docs/CODE_IMPORT.md) together when changing these contracts.

## Module size and code analysis

Work on `main` as specified in [AGENTS.md](AGENTS.md). See [CONTRIBUTING.md](CONTRIBUTING.md) for review and contribution guidance. Keep new functionality separated by responsibility rather than adding language switches, import UI or analysis endpoints to the largest files. Code analysis lives in `frontend/src/code`: contracts/catalog, lexical utilities, program families, specialized families, graph resolution/layout and cancellable worker client. Import routing is in `frontend/src/imports`; SQL/code API commands are in `storage/analysis-commands.ts`. Import dialog subcomponents, card summaries and Properties sections are independent. Backend code, SQL and spatial OpenAPI schemas and the MCP tool description are separate modules.

Continue extracting cohesive responsibilities when touching large App, Properties, editor and Repository files. Avoid a broad rewrite mixed with a new feature. Family analyzers must ignore comments/nonstructural strings, preserve original line evidence, bound work and report uncertainty instead of picking arbitrary duplicate symbols. Add a meaningful fixture for each supported language and cross-file tests for resolution/ambiguity. API tests verify read-only preview, transactional save, grant/consent revocation and metadata/export preservation. [Code import](docs/CODE_IMPORT.md) is the supported capability contract.

Stateful classes own storage, session, simulation, narration and export lifecycles; React components present and subscribe to them. Optional views/commands use dynamic imports at their actual usage boundaries, while essential revocation and cleanup owners remain mounted. Check the built entry and its static import closure after a split: moving source files alone does not defer execution or downloads. Keep missing-module recovery and originating-session guards intact; use build output and browser checks instead of increasing the chunk warning threshold. See [architecture](ARCHITECTURE.md#module-loading-and-ownership).
