# Public website and workspace routes

The product website is generated by Hugo. The editor is at `/app/`; `/` is an informational product homepage. Moving between these paths preserves the exact origin and the existing `visual-nerve-cache` IndexedDB workspace. Changing the hostname does not: export on the old origin and restore on the new one.

## Pages and content

- `/`: positioning, device screenshots, an editable kiosk example and product entry points.
- `/features/`, `/use-cases/`, `/process-simulator/`, `/mcp/`, `/developers/`: English, source-verified capabilities and workflows.
- `/privacy/`, `/security/`, `/license/`: data flows, trust boundaries and licensing.
- `/help/`: 16 task guides with search and actual screenshots.
- `/app/`: the native editor, mandatory browser-storage consent and optional local integration.
- `/api/docs/`: bundled reference, with no Analytics or consent scripts.

Public product pages use `layout: product`. Shared site metadata, navigation, footer and responsive styling live in `hugo/layouts/partials/` and `hugo/static/site/`. Help and the editor keep compact native navigation. The website uses the same saved Appearance; System is the default.

Every page uses the native orange command-symbol logo. Public navigation adds the same full-width divider under the header as the editor, Help and API reference; its inner content remains constrained for readability.

The homepage demo link `/app/?demo=kiosk` creates the bundled kiosk template using the same authoritative template path as New diagram. It runs only after required storage acceptance. A successful local save removes the parameter to prevent duplicate diagrams on reload. No user model is supplied through a URL.

## Device screenshots

`frontend/tests/e2e/site-screenshots.spec.ts` captures four distinct, real app diagrams at 360×640, 1024×1366, 1440×1080 and 1920×1080 CSS pixels. The device arrangement follows the provided reference: monitor behind, tablet left, phone in front and laptop right. The laptop screen is exactly 4:3 and the phone screen exactly 9:16, with fresh captures at those proportions. Frames are neutral CSS illustrations without manufacturer names or device labels; the screens are unaltered viewport captures. The social-preview image is derived from the real desktop capture.

Other product-page screenshots use `screen-capture.html` and `captures.css`: landscape images have a neutral laptop frame with a 4:3 screen; tall portrait images have a phone frame with a 9:16 screen. Complete screenshots fit inside the screen with `object-fit: contain`; the content is never stretched or cropped. Cropped, nearly square dialog details use a plain detail panel at their native proportions. Surroundings remain transparent in both themes. The existing Help image hook keeps plain, full-size-link screenshots for reading documentation.

Build first, then explicitly opt in:

```sh
cd frontend
VN_CAPTURE_SITE=1 npm run test:e2e -- site-screenshots.spec.ts
```

Use the host's Chrome path through `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` when needed. Capture requires `cwebp`; normal CI never regenerates these images. Review the final device composition and individual screenshots visually after regenerating them.

## Consent and Analytics

Klaro 0.7.21 is pinned, locally bundled and retains its BSD-3-Clause license plus bundled component notices. `scripts/consent-assets.mjs` reproduces vendor files from installed dependencies; no CMP CDN request is needed. The build records licenses.

Set repository variable `GOOGLE_ANALYTICS_MEASUREMENT_ID` to the real GA4 Measurement ID. Deploy workflows pass it as `HUGO_PARAMS_GOOGLEANALYTICSMEASUREMENTID`. The configured project ID is `G-1P74HBXS87`; it is a public identifier, not an access secret.

Explicit, default-off consent is required before the Google tag loads. Basic gating sends no denied-mode pings. Exactly nine public page routes are eligible. Editor, Help and API docs never load the tag, including after consent elsewhere. Only sanitized origin/path and a fixed title are supplied; queries, fragments, referrers and workspace content are excluded. Ordinary Google request metadata remains external.

**Disable Enhanced Measurement in the GA4 web data stream before activating the property.** Remove Connected Site Tags or custom automatic tags/events that read page URLs or DOM content. These account-level settings cannot be inspected or changed using a Measurement ID alone. The integration disables Google signals and ad personalization, denies all advertising storage and sends its own page_view. Do not add Tag Manager tags, enhanced-measurement events or custom events reading app DOM, content or URL queries.

Cookie settings provides equal acceptance/rejection and withdrawal. Choices live in two localStorage keys for up to 30 days, separately from IndexedDB storage consent. Withdrawal disables the loaded tag, clears accessible analytics cookies and reloads the page; it cannot retract earlier network requests. Without a configured ID, no tag runs and the settings control explains that no optional analytics is configured.

The app's required local-storage acceptance is independent of optional website tracking. Site consent is not imported/exported with workspace backups.

## SEO and environments

`SITE_URL` sets Hugo's absolute base URL. `HUGO_PARAMS_ENVIRONMENT` is `staging` or `production`. The default build is staging at `https://visualnerve.caripson.com/`, with noindex/nofollow and a robots exclusion for all paths.

Production uses `https://www.visualnerve.com/`, self-canonical metadata, Open Graph/Twitter previews, a SoftwareApplication schema and a generated sitemap. The workspace remains noindex and is excluded from the sitemap; robots also excludes workspace and command endpoints. Public documentation has no imported user content.

The static bundle audit allows only named website pages, curated screenshots, pinned assets and licenses. No workspace backups, user exports or database files are uploaded. Deployment remains manual; see [deployment gates](DEPLOYMENT.md).

## Verification

`site-seo.test.ts` builds both environments and checks canonical domains, robots, sitemap and workspace exclusion. `site.spec.ts` checks public links/anchors, metadata, screenshots, 1440/768/390/320px light/dark navigation and fresh-page storage. `site-consent.spec.ts` intercepts a synthetic Google tag to test opt-in, rejection, sanitization, withdrawal, expiry and private-route exclusion without sending real analytics.

App routing, legacy-origin persistence, offline aliases and demo reloads have dedicated browser regressions. Help search checks result placement, keyboard actions, touch sizes and focus gutters. Full CI runs the shared Go/frontend/build/browser checks before an eligible staging or production release.
