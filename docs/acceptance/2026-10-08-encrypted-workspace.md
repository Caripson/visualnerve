## Architecture and storage coverage

| Boundary                | Implementation and responsibility                                                                                                                                                                                          |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Cryptography            | `VaultCrypto`: native AES-256-GCM, authenticated record context, password/recovery wrapping and separately derived HMAC index/authentication keys.                                                                         |
| Logical records         | `VaultLogicalRecordCodec`: encrypted root manifests, authenticated ordered chunks and encrypted query projections.                                                                                                         |
| Durable commits         | `VaultRecordStorage`, `VaultJournal`: short native IndexedDB transactions, revision/epoch checks and coordinated preparation outside native transactions.                                                                  |
| Application storage     | `EncryptedWorkspaceDatabase`, `Repository`, `Workspace`: explicit transaction scopes and originating-session operations for UI, history, simulation, API and MCP.                                                          |
| Session and maintenance | `VaultSession`, `VaultGate`, `WorkspaceTransferBoundary`: human unlock/recovery, deadline enforcement, revocation and settled cleanup before re-entry. Transfer and key rotation verify contents before atomic activation. |
| Temporary narration     | `PresentationPlayer`, `NarrationClipStore`: complete-tour preparation, bounded retained clips and disposable encrypted overflow with RAM-only keys.                                                                        |

The logical workspace schema is **8**, independent of physical vault schema **1**. All 14 logical stores use the encrypted backend: `diagrams`, `nodes`, `edges`, `owners`, `settings`, `templates`, `datasets`, `historySnapshots`, `historyContents`, `historySources`, `historyRows`, `simulationModels`, `simulationRuns`, `simulationCheckpoints`. Physical vault stores are `metadata` and `records`; technical control/header metadata remains readable. Workspace content and logical identifiers are encrypted or represented by keyed tokens.

The isolated app uses `visual-nerve-vault`; existing `www`/staging workspaces retain the legacy plaintext `visual-nerve-cache`. Changing source or deploying a new package does not encrypt old browser records. See [schema and limits](../ENCRYPTED_WORKSPACE_SCHEMA.md), [storage](../STORAGE.md), [privacy](../PRIVACY.md), [API security](../../API.md#encrypted-workspace-security) and [MCP security](../MCP.md#encrypted-workspace-security).

On macOS the recorded browser runs use installed Chrome through `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. Synthetic certificate/DNS exceptions belong only to the isolated E2E fixture. Playback requires a one-second decoded clip within **0.001 s** and non-silent peak greater than **0.1**; preload completion requires exact readiness counts, progress 1 and zero new preparation requests on replay.

Password wrapping defaults to **600,000 PBKDF2-SHA-256 iterations**, accepting 600,000–2,000,000. Physical plaintext records are bounded to **16 MiB / 2 million values / depth 64**; logical records use bounded chunks and permit up to **1 GiB / 64 million values**. These are rejection ceilings, not browser memory/quota guarantees. Full-tour preparation retains **32 MiB** of prepared clips in RAM and spills encrypted temporary clips up to **1 GiB including IV/tag overhead**; a working clip can add up to 32 MiB, and inference has separate memory needs. Capacity/quota failure must not report 100%. `buffered` counts retained distinct narrated clips; progress counts ready requested steps, including blanks and duplicates. See [speech semantics and cleanup](../SPEECH.md).
