## Architecture and compatibility

Simulation truth still belongs to the shared deterministic engine and semantic document model. Card heights, capacity banks and exports are projections; they do not create business nodes or change capacity. Frozen runs own their assumptions, scenario labels, currency and results. Canvas selection can be detached without destroying those records.

The additional modules keep specific responsibilities outside large components: `SimulationCardSizing`, `SimulationExportScene`, `GroupMembership`, `QuickAddPlacement`, clipboard validation, canonical canvas geometry, topology signatures and the canvas run lifecycle. IndexedDB remains the local persistence layer. Existing document and Process Simulator schema versions remain compatible; no backend or database is added.

API, MCP and OpenAPI descriptions document captured run metadata, structured currency mismatch errors and the separate editability of primary versus additional/compact capacity cards. Help explains topology detachment and failed access-save recovery. Shared simulator controls continue using the same service as programmatic clients.

## Verification scope

The full regression suite covers creation/editing, mind maps, groups, history, persistence and multi-tab conflicts; CSV/SQL/code/Visio/draw.io import and analysis; filters/views and source refresh; simulation wizard, hierarchy, shared resources, scaling, scenarios, deterministic UI/API/MCP execution; 2D/3D transitions/movement/navigation; drawing, status, presentation/storyboard/video exports; rendered/semantic exports; public pages, consent/privacy, help/search, theme, mobile panels and API documentation.

Headless mobile and scaling checks exposed a stable-frame scheduling stall before input dispatch. Traces showed no moving-button retries; the affected canvas contained three fixed nodes, 13 rendered particles and two paths. Independent source review found no corresponding application loop. Instrumented reproduction recorded normal timers and animation frames in six passing cases, but the unchanged original tests still failed once in twelve runs. With the same fixed Chrome version and GPU acceleration disabled, all twelve original checks passed, followed by the actual mobile relief and two decoded movie exports. `VISUAL_NERVE_E2E_DISABLE_GPU=1` makes that local diagnostic reproducible without changing production code, forcing input, suppressing tracing or skipping assertions. The evidence is consistent with a local browser rendering problem, but does not establish its exact native cause or claim physical-device coverage.

The mobile test helpers and relief case are now separated into `mobile-fixtures.ts` and `mobile-spatial.spec.ts`; no cases or assertions were removed. Final whole-product browser verification uses a fixed Google Chrome 154.0.8037.98 binary with the local software-rendering option, standard CI tracing, actual H.264 decoding and explicit screenshot capture. CI retains its default Playwright browser configuration. The live speech audit downloads the pinned Alan model, verifies non-silent decoded PCM, warm reuse and offline playback. It is opt-in so ordinary offline CI does not depend on external model hosting.

The final live Alan audit passed with a cold start of 9,740 ms and a warm start of 1,946 ms on this machine/network. Three actual decoded clips were 4.21–4.28 seconds long at 44,100 Hz with peaks above 0.82; all three started playback. Warm and offline preparation requested no additional model downloads. These are observed timings, not a cross-device latency guarantee.

The Safari audio experiment uses cached WebKit with its matching Playwright driver: fresh desktop/mobile-emulated contexts, identical local WAV data and a six-second delay. It tests the actual `Narrator` class, rather than a substituted audio implementation. Device dimensions/touch behavior are emulated; this audit does not claim physical iPhone/iPad coverage or full Safari product certification. Automated accessibility checks supplement, rather than replace, assistive-technology testing.

## Final results

All local release checks passed on 8 October:

- Whole-product browser audit: **212/212 passed in 19.0 minutes**, including every opt-in Help/site/process screenshot capture and live Alan speech check. It used fixed Chrome 154.0.8037.98, the documented local software-rendering option and ordinary trace/snapshot diagnostics.
- After the final preference error-recovery correction, the complete frontend suite passed **1,769 tests across 183 files**. The targeted Workspace checks also passed **94/94**, including 13 error-ownership regressions.
- The production build passed TypeScript, Vite, generated OpenAPI, Hugo, Go compilation, offline-shell generation and static-bundle auditing. The offline shell contains **129 local assets**; the static audit checked **488 application files** and found no user data files.
- Browser verification of the final production build passed **9/9 privacy/backup flows in 44.7 seconds**. The existing reminder case was strengthened with a native IndexedDB quota failure: it failed against the previous bundle at the stale Saved indicator, then passed after the correction, including retry and immediate reload.
- Go race tests, Go vet, Prettier and `git diff --check` passed.
- `npm audit --omit=dev` reported **zero known vulnerabilities** in production dependencies. This checks the advisory database, rather than certifying the absence of all security defects.
- **34 Help screenshots, four public device views and 18 acceptance images** were regenerated from synthetic application data. Representative mobile, hierarchy and public layouts were visually inspected.
- An independent final review found no additional blocker, removed assertions, unexpected diagnostic files or incompatible API/schema changes.

The whole-product browser audit preceded the final isolated preference error-recovery correction; the complete code suite, production build and nine relevant browser flows were rerun afterward. GitHub CI runs the complete regression suite for the pushed commit with its default Playwright graphics configuration. Commit and CI identifiers are provided in the release response. No deployment workflow was changed or dispatched.
