# Infrastructure capacity acceptance

This records implementation evidence for the infrastructure-capacity goal. The implementation builds on Process Simulator and its existing encrypted persistence, worker execution, graph editing, API and MCP. Production publication remains manual; local verification is not a deployment claim.

## Release scope

- `api-compute-capacity`: API & Compute Capacity.
- `network-multi-site-capacity`: Network & Multi-Site Capacity.
- `energy-power-capacity`: Energy & Power Capacity.
- `datacenter-capacity`: a combined, explicitly assumed datacenter example.
- Existing simulation schema 1 remains supported with unchanged numerical behavior. Infrastructure uses model schema 2 and infrastructure schema 1 so an older engine cannot silently ignore its processing semantics.
- Capacity planning covers reserved CPU, memory lifetimes, shared link throughput and energy/storage balances. OS scheduling, GC, packet-level TCP and electrical AC/DC power flow are outside this implementation.

## Work sequence

1. Define canonical units, versioned contracts, validation and bounded numerical services.
2. Integrate leases, transfer completion and energy supply into the existing deterministic event engine.
3. Preserve references through editing, copying, deletion, native exchange, archives and encrypted backup.
4. Implement examples, domain setup/editors, metrics, traffic indicators and scenario comparisons.
5. Expose the same configuration and metrics through existing API/MCP discovery and commands.
6. Complete English Help, method/limit documentation, actual screenshots and accessibility checks.
7. Run regression checks, commit/push main and verify CI. Production publication remains a separate owner-requested operation.

## Verification record and limits

- The complete frontend suite passed 4,480 tests across 385 files before the last focused refinements. Final-change checks additionally cover database contention, aggregate presentation, optional-description validation, exact acceptance numerics and encrypted/offline browser execution. These are not additive unique test totals.
- The independent boundary audit passed 272 tests across 23 existing security/storage/collaboration/offline files. Go race tests and vet, TypeScript, formatting, OpenAPI regeneration and the production build passed.
- New browser flows use isolated synthetic profiles at 390, 768 and 1440 pixels. Real screenshots were reviewed in both appearances; the Help suite also verifies its 320-pixel breakpoint. The five domain browser cases passed. The broader nine-file batch passed 35 of 39 cases initially; its four failures then passed unchanged in fresh invocations, including the dedicated encrypted/offline case. One initial failure was a native Chrome context-creation stall before the test body; another state request returned correct queue data after the predicate deadline. Assertions and timeouts were not relaxed.
- On the local macOS/Chrome/Node 22 test environment, the final bundle audit measured a 358,504-byte entry, 928,089 bytes of initial static imports and a 382,109-byte largest main-thread chunk. Existing budgets remain unchanged. Factories and domain UI load outside native IndexedDB transactions; cold initialization/restore/clear tests cover that boundary.
- There is no new database/store migration. Existing encrypted records retain the model, scenarios and captured run data. Model schema 2 / infrastructure schema 1 is an execution contract extension; legacy model schema 1 remains supported.
- No infrastructure-specific million-request throughput or hardware benchmark is claimed. Rendering reuses bounded Canvas sampling and aggregate cards; the existing legacy million-item regression verifies the underlying retention boundary, not every infrastructure workload.
- Infrastructure live collaboration is explicitly rejected until a negotiated shared contract exists. CPU/RAM scaling remains supported; automatic bandwidth/energy scaling and energy resource schedules are rejected. Generation windows control energy supply.
- CPU means dedicated reservations, network means fluid byte sharing plus explicit propagation, and energy means aggregate supply/storage balance. OS timeslicing, GC, TCP packets/congestion and AC/DC electrical topology are outside scope.
- Continuous floating-point integrals compare using the tolerance in `INFRASTRUCTURE_CAPACITY.md`; discrete counts, event order and capacities remain exact. Browser elapsed time is never simulated duration.

CI for the committed revision is the final full-suite gate; its outcome is reported with the delivery. Production deployment is not triggered by this goal.
